Installation and usage tutorial

Install the client for your platform, connect your AI service, then test a local task or pair another device.

  1. Install a client

    Use the platform instructions below to choose the package for your system. Open AsterHand, then check the operating system grants shown in Settings.

  2. Connect your AI service

    Open Settings → AI Connection. For ChatGPT, complete sign-in in the authorization window. For a compatible API, enter your HTTPS service address and API key. Save the connection, open Model & Reasoning, choose an available model and send a short test message.

  3. Pair a receiver

    Enable Remote Connections on both clients and make sure they can reach one another. Search for the receiver, enter a pairing code or send a request to its IP address. On the receiver, verify the device identity and select Allow once, Always allow, or Reject.

  4. Set receiver permissions

    Grant screen, Accessibility, ADB or Root only for the tools you plan to use. On Android, the permission level determines which tools run. On iOS, local AI screen access and remote screen access have separate controls.

  5. Run a first task

    Select a project, conversation and execution target. Start with “List the files in this project without changing anything.” Check which device handled the task and review its result. Inspect the target screen before sending touch or keyboard input.

If discovery does not find the receiver, check both clients’ Remote Connections settings and local-network permissions. Try a pairing code or the receiver’s IP address on the same reachable network. If a tool is denied, review its specific permission on the receiver before retrying.

PLATFORM INSTALLATION

Install AsterHand

Choose your operating system, processor or jailbreak environment. The steps below include the checks to make before you pair a device.

Windows

0.1 testing · Windows 7 SP1 or later · .NET Framework 4.6.2 or later

  1. Run AsterHand-Windows-Setup.exe to install for your Windows account, then open AsterHand. For the portable version, save AsterHand-Windows.exe in a folder you can write to and run it there.
  2. Open AsterHand. Configure your AI connection in Settings, then use Remote connections to discover or pair a receiver.
  3. If the app fails to launch, check that the system has .NET Framework 4.6.2 or newer. If the app opens but a paired receiver cannot be reached, check Remote connections on both devices and confirm the local network allows them to communicate.
Download installer Download portable EXE

macOS

0.1.4 preview · Intel: macOS 10.15+ · Apple silicon: macOS 11+

  1. Open Apple menu → About This Mac to check the processor. Download the matching ZIP, extract it, move AsterHand.app to Applications, then open it there.
  2. The preview uses ad hoc signing. If macOS asks you to review the app, open System Settings → Privacy & Security. For screen viewing and control, grant Screen Recording and Accessibility as needed. A new build may require these grants again.
  3. Return to AsterHand after granting permissions. Open Settings and check the permission state before testing a local screenshot. If macOS asks you to quit and reopen the app, do so before testing.
Download Intel ZIP Download Apple silicon ZIP

Linux

0.1.0 preview · Graphical Debian/Ubuntu desktop · amd64 or arm64

  1. Run uname -m to check your processor. Use amd64 for x86_64 and arm64 for aarch64.
  2. Install the DEB using your package manager, or run the command below from the download directory. Open the GUI as your regular user.
  3. X11 local input uses xdotool. Wayland currently lacks local input injection, and screen capture may show a system sharing prompt. A paired phone uses its own input permissions.
  4. If the app opens but you cannot take a Wayland screenshot, make sure PipeWire, xdg-desktop-portal and your desktop’s portal backend are running. Choose the screen or window when the desktop asks what to share.

Android

1.0 preview · Android 6.0 minimum build target · Development-signed APK

  1. Download AsterHand-1.0-Android.apk, then open it with the Android package installer.
  2. Choose Standard, ADB or Root in AsterHand. Standard mode needs applicable screen and accessibility permissions. ADB needs authorized debugging. For Root mode, approve the request in your device’s existing Root manager.
  3. Test a read-only action at the chosen permission level. If the receiver is paired but screen tools are unavailable, check the applicable screen permission on the phone and the remote screen setting in AsterHand.

iOS

1.0 preview · Compatible jailbreak required · Rootful iOS 14+ · Rootless and RootHide iOS 15+

  2. Open AsterHand, connect your AI service and enable the screen and Root permissions you intend to use.
  3. If the package manager reports a firmware or architecture mismatch, check the architecture below and use the package for the current bootstrap. Use the package manager to review any unresolved dependencies before proceeding.

Set up and test AsterHand MCP

MCP connects through the AsterHand control center on Windows, macOS or Linux and can use Android and iOS receivers you have paired. Start AsterHand and verify the receiver is online first.

  1. For a source install, prepare Node.js 20+, Python 3.11+, pnpm and the Codex CLI. Run the commands below to clone and install, or run only the final command from an existing repository root. The installer registers asterhand and keeps your other MCP entries.
  2. With the packaged Mac app, you can use its bundled installer. In Finder, choose Show Package Contents on AsterHand.app, open Contents → Resources, and run Install Codex MCP.command.
  3. Open a new Codex conversation and ask it to call devices_list. Verify the exact device with device_info and use screenshot to inspect the screen. Start with a read-only task and check the result on the device.
  4. If the tool is missing, check that Codex registered asterhand and reopen the conversation. If the tool is listed but the receiver is offline, check that the desktop control center is open and the existing pairing is reachable.

A FEW THINGS TO KNOW

Before you connect.

Does AsterHand root or jailbreak my device?

No. It uses Root, ADB, jailbreak helpers and screen capabilities that you have already enabled and authorized. AsterHand does not perform a jailbreak or grant those permissions by pairing.

Does “local agent” include an offline AI model?

The agent executes tools on your device. Model inference comes from the AI service you select; an offline model is not bundled. Messages, attachments and tool results needed for inference are sent to that selected service.

Which iOS build should I install?

Check dpkg --print-architecture in an existing device terminal. iphoneos-arm matches Rootful, iphoneos-arm64 matches Rootless, and iphoneos-arm64e matches RootHide. The current AsterHand targets are iOS 14+ for Rootful and iOS 15+ for Rootless/RootHide; target compatibility is not a guarantee for every jailbreak.

See the iOS installation guide
Where are the source and release files?

Source and platform documentation are on GitHub. Available client installers are in the main project's Releases. Original AsterHand code has no open-source license grant; third-party notices and licenses remain in effect.
